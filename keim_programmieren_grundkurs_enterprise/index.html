Programmieren lernen mit Keim

Diese Schulung erklärt Programmierung allgemein – so wie ein klassischer Python-, JavaScript-, Java- oder C#-Grundkurs. Keim ist hier die Unterrichtssprache. Es geht nicht primär um Simulationen, sondern um Variablen, Datentypen, Listen, Maps, Funktionen, Module, Objektorientierung, Fehlerbehandlung, Dateien und APIs.

0. Vorwort: Die Genesis von Keim

Die Vision

Keim wurde nicht als weitere Skriptsprache für den Alltag entwickelt, sondern aus einer tiefen Unzufriedenheit mit einer Software-Landschaft, die oft immer schwerer, indirekter und abhängiger wird. In einer Zeit, in der Programme sich hinter vielen Abstraktionsebenen verstecken, entstand der Wunsch nach einer souveränen Technologie: verständlich, kontrollierbar, lokal ausführbar und offen für die Nähe zur Maschine.

Die Sprache wurde von Ralf Krümmel im Mai 2026 erschaffen, unter dem Leitbild des Deep-Substrate Architects. Das Ziel war eine Umgebung, die die rohe Kraft nativer Ausführung mit der Lesbarkeit moderner Logik verbindet, ohne dabei zwingend von Cloud-Diensten oder fremden Frameworks abhängig zu sein. Keim richtet sich an Menschen, die Programmieren wieder als bewusstes Handwerk verstehen wollen: präzise, effizient, unabhängig und erklärbar.

Warum der Name „Keim“?

Der Name ist Programm. Ein Keim ist die kleinste, hochkonzentrierte Einheit eines entstehenden Systems. Er trägt einen Bauplan in sich, benötigt wenige Ressourcen und kann dennoch zu etwas Komplexem wachsen.

  • Potenzial: Ein kleines Keim-Programm kann durch Tabellen, Karten, Agentenlogik, HTTP-Routen und Hotspot-Ausführung zu einem massiven System heranwachsen.
  • Ursprung: Keim steht für den Anfang von etwas Neuem und für die Rückbesinnung auf das Wesentliche: Daten, Zustand, Regeln, Ausführung.
  • Wachstum: Die Sprache ist darauf ausgelegt, organisch zu wachsen: vom ersten Wert im Speicher bis zum autonomen Dienst, der Anfragen verarbeitet und seinen Zustand verwaltet.

Der Weg zur v4.3.3

Was als Experiment zur Simulation biologischer Prozesse begann, hat sich zu einer General Purpose Language entwickelt. Mit Version 4.3.3 besitzt Keim zentrale Bausteine moderner Programmierung: Datentypen, dynamische Collections, Module, Klassen, Objekte, Vererbung, JSON, HTTP-Routing, Fehlerbehandlung, Garbage Collection, Native-Hotspots und eine autonome API-Architektur.

Diese Schulung ist deshalb mehr als eine Syntaxübersicht. Sie ist eine Einladung, Programmieren als kontrollierbares Systemdenken zu lernen: Was ist ein Wert? Was ist Zustand? Wann verändert sich etwas? Welche Grenze trennt einfache Logik von robuster Architektur?

Willkommen in der Welt von Keim.

1. Ziel des Kurses

Nach dieser Schulung sollst du eigene Programme in Keim schreiben können. Nicht nur Simulationsprogramme, sondern typische Anwendungen: kleine Rechenprogramme, Textverarbeitung, Konfigurationsprogramme, Datenverarbeitung, Web-APIs, Objektmodelle und einfache Tools.

Du lernst Begriffe

Variable, Typ, Ausdruck, Bedingung, Schleife, Funktion, Objekt, Klasse, Fehler, Modul, API.

Du lernst Denken

Ein Programm ist eine Folge klarer Zustandsänderungen. Daten werden gelesen, geprüft, verändert und ausgegeben.

Du lernst Praxis

Jedes Kapitel enthält Keim-Beispiele, typische Fehler und kleine Übungen.

Wichtig: Die Syntax von Keim ist bewusst deutsch und lesbar. Trotzdem gelten die gleichen Grundideen wie in anderen Programmiersprachen.

1. Wie Programmieren funktioniert

Ein Computerprogramm besteht aus Anweisungen. Eine Anweisung sagt dem Computer, was als Nächstes passieren soll. Programme arbeiten fast immer nach diesem Muster:

SchrittFrageBeispiel
EingabeWelche Daten kommen rein?Name, Alter, JSON-Request, Dateiinhalt
VerarbeitungWas wird berechnet oder entschieden?Ist das Alter über 18? Wie hoch ist der Preis?
ZustandWas wird gespeichert?Benutzer, Warenkorb, Einstellungen
AusgabeWas kommt heraus?Text, JSON, Datei, HTTP-Antwort

Imperatives Denken

Imperativ bedeutet: Du gibst Schritt für Schritt Befehle. Beispiel: Setze eine Zahl, erhöhe sie, gib sie aus.

speicher zaehler ist ganzzahl = 0
setze zaehler auf 1

Deklaratives Denken

Deklarativ bedeutet: Du beschreibst, was gelten soll. Keim mischt beide Denkweisen. Eine Route beschreibt zum Beispiel, welcher Pfad beantwortet wird:

server api bei 18080 parallel 4:
    route GET "/health" antwortet speicher antwort:
        setze antwort auf "{\"ok\":true}"

4. Variablen & Speicher

In vielen Sprachen heißen benannte Werte Variablen. Keim nennt sie häufig speicher, weil sie einen Zustand halten. Eine Variable ist wie eine beschriftete Schublade.

Variable anlegen

speicher alter ist ganzzahl = 36
speicher preis ist zahl = 19.99
speicher name ist text = "Ada"
speicher aktiv ist bool = wahr

Variable ändern

setze alter auf 37
setze name auf "Grace"
setze aktiv auf falsch

Warum Typen wichtig sind

Der Typ sagt, welche Operationen sinnvoll sind. Eine Zahl kann man addieren. Einen Text kann man verketten. Eine boolesche Variable wird für Entscheidungen verwendet.

Typischer Anfängerfehler: Einen Text wie "42" mit einer Zahl 42 verwechseln. Beides sieht ähnlich aus, ist aber nicht dasselbe.

7. Texte

Textwerte heißen in vielen Sprachen Strings. In Keim ist der Typ text.

speicher vorname ist text = "Ada"
speicher nachname ist text = "Lovelace"
speicher name ist text = vorname + " " + nachname

Text als Datenformat

JSON ist technisch ebenfalls Text, aber mit einer festen Struktur:

speicher raw ist text = "{\"name\":\"Ada\",\"alter\":36}"
speicher obj ist karte

json liest speicher raw in speicher obj

Escaping

Wenn ein Text selbst Anführungszeichen enthält, müssen sie maskiert werden:

speicher antwort ist text = "{\"ok\":true}"

8. Tupel, Listen und Karten

Fast jedes echte Programm braucht mehrere Werte. Dafür gibt es Container.

8.1 Tupel

Ein Tupel ist eine feste Gruppe von Werten. Klassisch: Koordinaten, RGB-Farben, Datumsteile.

# Konzeptuelles Tupel:
# position = (x, y)
speicher x ist zahl = 10.0
speicher y ist zahl = 20.0

Keim v4.3.3 nutzt für feste kleine Gruppen aktuell meist Objekte, Karten oder mehrere Speicher. Ein expliziter Tupel-Typ ist ein sinnvoller nächster Sprachschritt. Bis dahin modelliert man Tupel so:

karte position setzt "x" auf 10.0
karte position setzt "y" auf 20.0

8.2 Listen

Eine Liste enthält mehrere Werte in Reihenfolge. Sie ist gut, wenn du alle Elemente durchgehen willst.

speicher zahlen ist liste mit ganzzahl
liste zahlen fuegt 10 hinzu
liste zahlen fuegt 20 hinzu
liste zahlen fuegt 30 hinzu

Typische Listenoperationen:

OperationBedeutung
hinzufügenneuen Wert ans Ende setzen
lesenWert an Position holen
entfernenWert löschen
längeAnzahl der Elemente bestimmen

8.3 Karten

Eine Karte speichert Werte unter Schlüsseln. Andere Sprachen nennen sie Dictionary, Map, HashMap oder Objekt-Literal.

speicher benutzer ist karte

karte benutzer setzt "name" auf "Ada"
karte benutzer setzt "alter" auf 36
karte benutzer setzt "aktiv" auf wahr

karte benutzer liest "name" in speicher name

Präsenztest

wenn karte benutzer enthaelt "email":
    karte benutzer liest "email" in speicher email
Übung: Erstelle eine Karte produkt mit Name, Preis und Lagerbestand. Lies den Preis in einen Speicher.

9. Kontrollfluss: Wenn, Schleifen, Ablauf

Kontrollfluss entscheidet, welche Anweisungen ausgeführt werden.

Wenn-Bedingungen

speicher alter ist ganzzahl = 20
speicher meldung ist text = ""

wenn alter >= 18:
    setze meldung auf "volljaehrig"

Warum Einrückung wichtig ist

Alles, was eingerückt unter wenn steht, gehört zum Bedingungsblock.

wenn aktiv:
    setze status auf "läuft"
    setze zaehler auf zaehler + 1

Schleifen

Schleifen wiederholen Code. In Keim-Projekten gibt es häufig jede runde für wiederkehrende Abläufe.

jede runde:
    setze zaehler auf zaehler + 1

Für typische Anwendungslogik wird oft ein Host oder ein Serverloop genutzt: HTTP-Requests lösen Code aus, statt dass man manuell eine Endlosschleife schreibt.

Verzweigung in APIs

wenn karte api_befehl enthaelt "running":
    karte api_befehl liest "running" in speicher running

10. Funktionen

Eine Funktion ist ein benannter Codeblock, der eine Aufgabe erledigt. Funktionen machen Programme kürzer, testbarer und verständlicher.

Warum Funktionen?

  • Du vermeidest Wiederholung.
  • Du gibst einer Logik einen Namen.
  • Du kannst kleine Teile unabhängig testen.

Konzeptuelles Beispiel

funktion begruessung(name: text) gibt text:
    gib "Hallo " + name zurück

Je nach Keim-Prototypstand kann die genaue Funktionssyntax variieren. Das wichtige Prinzip bleibt: Eingaben hinein, Ergebnis heraus.

Funktionales Denken

BegriffBedeutung
ParameterWert, der in die Funktion hineingegeben wird
RückgabeWert, den die Funktion liefert
NebeneffektFunktion ändert Zustand außerhalb, z.B. Datei schreiben
Praxisregel: Funktionen sollten möglichst klein sein. Eine Funktion mit 100 Zeilen macht meist zu viel.

11. Module & Imports

Ein Modul ist eine Datei oder ein Namensraum, der zusammengehörige Funktionen, Klassen und Speicher enthält.

modul rechner:
    speicher version ist text = "1.0"

Warum Module?

Ohne Module landen alle Namen in einer Datei. Das wird schnell chaotisch. Module trennen Verantwortlichkeiten.

ModulVerantwortung
api_steuerungHTTP-Routen und JSON-Eingaben
benutzer_logikBenutzer prüfen und verwalten
datei_importCSV/JSON-Dateien lesen

Export

Export bedeutet: Dieser Name darf von außen benutzt werden.

export speicher standard_port ist ganzzahl = 18080

Klasse

klasse Benutzer:

    eigenschaft alter ist ganzzahl
    eigenschaft aktiv ist bool

Objekt

objekt admin ist Benutzer:
    name = "Ada"
    alter = 36
    aktiv = wahr

Dynamisches Objekt mit neu

speicher neuer_user ist referenz
neu Benutzer in speicher neuer_user

Vererbung

Vererbung bedeutet: Eine Klasse übernimmt Eigenschaften einer anderen Klasse und erweitert sie.

klasse Admin ist Benutzer:
    eigenschaft rechte ist text
KonzeptBedeutungBeispiel

Warum OOP? Wenn Daten natürlich zusammengehören, ist ein Objekt oft lesbarer als viele einzelne Variablen.

13. Fehlerbehandlung

Programme laufen nicht immer perfekt. Dateien fehlen, JSON ist ungültig, Netzwerk antwortet nicht, Eingaben sind falsch. Fehlerbehandlung verhindert, dass ein einzelner Fehler das ganze Programm beendet.

versuche / fange

versuche:
    json liest speicher request_body in speicher daten
fange fehler in speicher fehlertext:
    setze status auf 400
    setze antwort auf "{\"ok\":false,\"error\":\"ungueltiges JSON\"}"

Warum Fehler nicht ignorieren?

Ein ignorierter Fehler wird später oft zu einem schwer verständlichen Folgefehler. Gute Programme prüfen Eingaben früh.

SituationGute Reaktion
Ungültiges JSONStatus 400 und Fehlermeldung
Datei fehltAlternative oder klare Meldung
Unbekannte RouteStatus 404
Interner FehlerStatus 500, Logeintrag

Dateien speichern Daten dauerhaft. JSON ist gut für strukturierte Daten. CSV ist gut für Tabellen.

JSON lesen

speicher raw ist text = "{\"name\":\"Ada\",\"aktiv\":true}"
speicher daten ist karte

json liest speicher raw in speicher daten
karte daten liest "name" in speicher name

JSON schreiben

speicher antwort_obj ist karte
karte antwort_obj setzt "ok" auf wahr
karte antwort_obj setzt "service" auf "mein_programm"

json schreibt speicher antwort_obj in speicher antwort

Dateien als typische Aufgabe

Ein normales Tool liest häufig eine Datei, verarbeitet Inhalt und schreibt ein Ergebnis.

# Konzept:
# 1. Datei lesen
# 2. JSON parsen
# 3. Werte prüfen
# 4. neue Datei schreiben

15. HTTP und APIs

Eine API ist eine Schnittstelle, über die andere Programme mit deinem Programm sprechen können. HTTP ist das Protokoll, das auch Webseiten und Webservices verwenden.

Server definieren

server api bei 18080 parallel 4:
    route GET "/health" antwortet speicher antwort:
        setze antwort auf "{\"ok\":true}"

GET

GET wird genutzt, um Daten abzurufen.

route GET "/status" antwortet speicher antwort:
    setze antwort auf "{\"status\":\"bereit\"}"

POST

POST wird genutzt, um Daten an den Server zu senden.

route POST "/benutzer" liest speicher body antwortet speicher antwort status speicher status:
    versuche:
        json liest speicher body in speicher daten
        karte daten liest "name" in speicher name
        setze status auf 200
        setze antwort auf "{\"ok\":true}"
    fange fehler in speicher err:
        setze status auf 400
        setze antwort auf "{\"ok\":false}"

Warum parallele Handler?

Mehrere Clients können gleichzeitig anfragen. Keim v4.3.3 kann Routen parallel annehmen, mutierende Weltzugriffe aber deterministisch schützen.

Wichtig: Parallelität kann Race Conditions erzeugen. Deshalb schützt die Runtime gemeinsame Zustände mit Locks.

16. Zeit, Krypto und Prozesse

Zeit

Zeitfunktionen sind nützlich für Logs, Metriken, Timeouts und Dateinamen.

zeit jetzt in speicher jetzt

Krypto/Hashing

Hashing erzeugt einen Fingerabdruck von Daten. Das ist nützlich für Checksummen, IDs und Integritätsprüfung.

speicher passwort ist text = "geheim"
krypto sha256 speicher passwort in speicher hash

Externe Prozesse

Ein Programm kann andere Programme starten, zum Beispiel Systemtools oder Build-Skripte.

prozess fuehrt "echo Hallo" in speicher ausgabe
Sicherheitsregel: Baue niemals ungeprüfte Benutzereingaben direkt in Prozessbefehle ein. Das kann Command Injection erzeugen.

17. Debugging

Debugging bedeutet, Fehler im Programm zu finden und zu verstehen. Gute Entwickler raten nicht nur, sondern beobachten systematisch.

Die fünf Fragen

  1. Was habe ich erwartet?
  2. Was ist tatsächlich passiert?
  3. Welche Daten waren zu diesem Zeitpunkt im Speicher?
  4. Welche Anweisung wurde zuletzt ausgeführt?
  5. Ist der Fehler in Eingabe, Verarbeitung oder Ausgabe?

Typische Fehler

FehlerSymptomLösung
Falscher Port404 oder Verbindung fehlgeschlagenServerausgabe lesen: Port 18080 statt 8080
Ungültiges JSON400 oder Parse-FehlerJSON mit Validator prüfen
Falscher TypBerechnung schlägt fehlText/Zahl/Bool trennen
Fehlende Routeunbekannte RouteRoute im Serverblock registrieren
Einrückung falschCode läuft außerhalb von wennBlöcke sauber einrücken

Schrittweise testen

Teste kleine Teile einzeln. Nicht erst 500 Zeilen schreiben und dann alles starten.

21. Update v7.5: Was ist neu?

Dieser Abschnitt ergänzt den ursprünglichen v4.3.3-Grundkurs. Er ersetzt die Grundlagen nicht. Wer neu programmiert, soll weiterhin mit Speicher, Typen, Bedingungen, Listen, Karten, Funktionen und Projekten beginnen. v7.5 kommt danach: als Enterprise-Schicht für stabile Artefakte, Web-Integration, Runtime-Härtung und Schulung in realistischen Projektketten.

Was bleibt aus v4.3.3 wichtig?

  • Variablen und klare Datentypen
  • Karten, Listen, JSON und HTTP
  • Fehlerbehandlung und Tests
  • Module und Projektstruktur
  • verständliche Programme vor Optimierung

Was ergänzt v7.5?

  • KBC-STABLE-1 als stabile Bytecode-Spezifikation
  • Native-/WASM-Paritätsartefakte
  • Web-Projekt-Scaffold mit JS-Interop
  • Security/SBOM/Capabilities
  • Benchmark-/Kompatibilitätsmatrix und Browser-WASM-Harness

  1. Alte Beispiele ausführen: Prüfe zuerst, ob das Grundprogramm verstanden wurde.
  2. Modulstruktur ergänzen: Trenne Beispielcode, Tests und Build-Artefakte.
  3. Stabile Artefakte erzeugen: Bytecode, Lockfile, SBOM und Bericht.
  4. Runtime-Pfad vergleichen: Python-VM, Native/WASM-Manifest und Browser-Harness auswerten.

Nicht falsch migrieren: Eine Migration ist kein Umschreiben aller Einsteigerbeispiele. Erst wenn die Lernenden die Grundlagen können, wird die Enterprise-Kette ergänzt.

23. Architektur: Von Source bis Runtime

Keim v7.5 wird am besten verstanden, wenn man die Artefaktkette betrachtet. Ein Programm ist nicht nur Text. Es wird schrittweise in präzisere Formen überführt. 

Keim-Source
  ↓
Tokenizer / Parser
  ↓
Typed AST
  ↓
Bytecode / KBC-STABLE-1
  ↓
Verifier
  ↓
Python-VM / Native-VM / WASM-Harness
  ↓
Replay / Benchmark / Security Report

Warum diese Kette schulungstauglich ist

  • sichtbar: Jede Stufe kann als Datei betrachtet werden.
  • prüfbar: Der Verifier kann fehlerhafte Artefakte ablehnen.
  • vergleichbar: Differentialtests vergleichen verschiedene Laufzeitpfade.
  • erweiterbar: Neue Backends müssen dieselbe Semantik erfüllen.

Minimalbeispiel: eine Funktion als Systemartefakt

funktion addiere(a ist ganzzahl, b ist ganzzahl) gibt ganzzahl:
    rueckgabe a + b

Didaktisch kann daraus gezeigt werden:

  1. Welche Namen gibt es?
  2. Welche Typen haben die Namen?
  3. Welche Slots werden erzeugt?
  4. Welche Bytecode-Instruktionen entstehen?
  5. Welche Runtime führt diese Instruktionen aus?

24. KBC-STABLE-1 & Bytecode

KBC-STABLE-1 ist die stabilisierte Bytecode-Spezifikation der Enterprise-Schicht. Für Lernende ist wichtig: Bytecode ist die maschinennahe Zwischenform, aber noch nicht direkt CPU-Maschinencode.

Was KBC-STABLE-1 leistet

  • stabile Section-Struktur
  • Section-Checksums
  • Payload-Hash
  • Verifier-kompatible Struktur
  • Debug-/Kompatibilitäts-Metadaten

Warum das Enterprise-relevant ist

  • Builds werden reproduzierbarer.
  • Artefakte können geprüft werden.
  • Backends erhalten eine feste Zielstruktur.
  • CI kann Kompatibilität automatisiert prüfen.

Lehrübung

Aufgabe: Nimm ein einfaches Programm aus Kapitel 3 oder 10. Beschreibe ohne Code, welche Bytecode-Schritte vermutlich entstehen: Konstanten laden, Slots speichern, Werte addieren, zurückgeben.

Beispielhafte Befehle

python -m keim v74-spec --json
python -m keim v74-build examples/sprache_v74_enterprise_stabilization.keim --out build/v74_final
python -m keim v74-verify build/v74_final/app.kbcstable
Merksatz: Ein stabiles Bytecodeformat ist ein Vertrag zwischen Compiler, VM, Werkzeugen und Tests.

25. Typen, Result & Match

v4.3.3 vermittelt einfache Typen. Moderne Keim-Versionen ergänzen strukturierte Fehler- und Entscheidungsmodelle. Besonders wichtig sind ergebnis<T,E> und match.

Warum Result statt unklarer Fehler?

Bei APIs, Dateizugriffen und Simulationen kann eine Operation scheitern. Ein Result-Wert macht das sichtbar: 

funktion lade_zahl(textwert ist text) gibt ergebnis<ganzzahl, text>:
    wenn textwert == "":
        rueckgabe fehler("leer")
    sonst:
        rueckgabe ok(42)

Match als saubere Verzweigung

funktion nutze() gibt ganzzahl:
    speicher r ist ergebnis<ganzzahl, text> setzt lade_zahl("x")
    match r:
        fall ok(wert):
            rueckgabe wert
        fall fehler(err):
            rueckgabe 0

Schulungslogik

EinsteigerbegriffEnterprise-BegriffBeispiel
Wenn/Sonstkontrollierte VerzweigungWenn Alter > 18
FehlertextResult-Fehlerwertfehler("Datei fehlt")
Wert vorhanden?Pattern Matchingfall ok(wert)
Aufgabe: Schreibe eine Funktion, die eine Karte liest. Wenn der Schlüssel fehlt, gib fehler("nicht gefunden") zurück. Sonst gib ok(wert) zurück.

26. Native, WASM, GC & Heap

Keim hat in den neueren Versionen mehrere Runtime-Pfade bekommen. Für Schulungen muss das nicht als Low-Level-Detail beginnen. Die einfache Frage lautet: Wo läuft mein Programm?

Python-VM

gut für Entwicklung, Tests und Sichtbarkeit

Native-VM

Ziel für eigenständige Ausführung und Performance-Pfad

WASM

Ziel für Browser, Edge und portable Sandboxen

WASM-Heap-Runtime

WASM kennt von Haus aus nur Zahlen und linearen Speicher. Keim modelliert dynamische Werte daher über Tagged Values, Heap-Objekte und Runtime-Intrinsics. 

Tagged Value:
  int / bool / null / heap_ref

Heap Object:
  header
  type/kind
  size
  payload

GC-Entwicklung in Keim

VersionKonzeptLernwert
v6.8WASM Heap RuntimeWarum dynamische Werte Speicher brauchen
v6.9Mark/Sweep + HashmapWarum Speicher wieder freigegeben werden muss
v7.0Generational GCWarum junge Objekte anders behandelt werden
v7.1Compacting GC + Region AllocatorWarum Fragmentierung und temporäre Werte wichtig sind
Dozentenhinweis: Vergleiche Heap/GC mit einem Lager: Kurzlebige Dinge kommen auf den Arbeitstisch (Region), langlebige Dinge ins Regal (Heap), Müll wird entfernt (GC), Regale werden geordnet (Compaction).

33. Update v7.8.5: Programme ausliefern statt nur ausführen

Neu in der Schulung: v7.8.5 ergänzt den bisherigen v7.5-Enterprise-Teil um reale Auslieferung: Full Runtime Packager, GPU-aware Bundles, Self-Bootstrapping Launcher, internes PE64/ELF64-Linking und Projekt-Web-Overlays.

Was Lernende jetzt zusätzlich verstehen sollen

Runtime-Bundle

Ein Keim-Programm besteht nicht nur aus Source. Es kann mit Runtime, Manifest, Scripts, Web-Artefakten und optional GPU-Treiberplan ausgeliefert werden.

Launcher

Der native Launcher startet die gebündelte Runtime. Dadurch braucht der Startpfad keine externe C/C++-Toolchain.

GPU-aware

GPU-Treiber werden nicht blind vorausgesetzt, sondern als Manifest, Smoke-Test und Fallback-Plan behandelt.

Web Overlay

Wenn ein Projekt web/index.html enthält, wird diese Ansicht in den Web-Build übernommen und durch Keim-Artefakte ergänzt.

ModusEinfach erklärtWann im Kurs verwenden?

native-subsetDirekter nativer Pfad für unterstützte Teilmengen.Performance- und Compiler-Vergleich.
zipappPython-Single-File-Artefakt.Portables Unterrichtsartefakt.
directory-bundleEntpackter Ordner mit allen Dateien.Debugging, Inspektion, Prüfung.
