0. Preface: The Genesis of Keim

The vision

Keim was designed as a sovereign programming substrate: readable enough for training, close enough to the machine to reason about runtime, memory, native execution and delivery artefacts. The course therefore teaches syntax, but also system thinking: values, state, rules, fields, agents, modules and runtime boundaries.

Why the name “Keim”?

A keim, a seed or germ, is a compact unit that contains a plan for growth. A small Keim program can start with a few named values and grow into an HTTP service, a field simulation, a Web adapter, a native target or a runtime package.

Path to v4.3.3 and beyond

The original v4.3.3 course remains the foundation. Later v7.5 Enterprise chapters add stable bytecode, Result/Match, Web/WASM, security and hardening. Version v7.8.5 adds the delivery layer: full runtime packaging, self-bootstrapping launchers, GPU-aware packaging and verifiable bundles.

You learn thinking

You learn practice

Important: Keim uses readable German keywords, but the programming ideas are the same as in Python, JavaScript, Java or C#.

2. How programming works

A program consists of instructions. Most programs follow the same pattern: input, processing, state and output.

StepQuestionExample
InputWhat data comes in?Name, age, JSON request, file content.
ProcessingWhat is computed or decided?Is the age above 18? What is the price?
StateWhat is stored?User, cart, settings.
OutputWhat comes out?Text, JSON, file, HTTP response.

Imperative thinking

You give step-by-step commands.

speicher zaehler ist ganzzahl = 0
setze zaehler auf 1

Declarative thinking

You describe what should hold. A route declares which path answers a request.

3. Setup and execution

Programming as a state machine

Keim treats a program as controlled state transitions. Values are created, checked, transformed and emitted. This is useful in simulations, APIs and training because every step can be explained as an explicit change.

Key terms

TermMeaning
memory / SpeicherA named storage location with a type and a value.
fieldA computed space, grid or influence layer used by agents or simulations.
tracePersistent or temporary evidence left by agents or rules.
agentAn entity that carries state and acts according to rules.
runtimeThe execution layer that interprets, compiles, packages or hosts the program.

18. Debugging

The five questions

  1. What input did I give?
  2. What did I expect?
  3. What actually happened?
  4. Where is the first wrong state?
  5. Which smallest change proves the cause?

Typical errors

Wrong type, wrong indentation, wrong path, occupied port, invalid JSON.

Test step by step

Change one thing at a time and keep runnable intermediate states.

v7.5 keeps the original training model but adds enterprise-grade runtime concepts: stable bytecode, a clearer value model, Result/Match, Web/WASM targets, capabilities, SBOM and hardening.

25. KBC-STABLE-1 and bytecode

The architecture can be taught as a chain: source → parser → semantic analysis → bytecode/runtime model → interpreter/native/WASM execution → tests → package → verification.

Why this chain matters

It gives learners a map from a line of source code to a deliverable artefact and shows where errors, security checks and performance decisions enter.

26. Types, Result and Match

KBC-STABLE-1 gives the course a stable intermediate representation. Learners can compare source-level intent with runtime-level operations.

Example

A typed value declaration becomes a value allocation plus metadata. That makes type errors, package manifests and bytecode tests easier to explain.

27. Native, WASM, GC and heap

Keim uses memory management topics to show why high-level values still need low-level lifecycle rules. Region allocation is fast for short-lived groups. Hashmaps support dynamic lookup. GC recovers unused objects. Compaction improves locality but can invalidate raw references if not handled carefully.

28. Web apps and JS interop

Capabilities restrict what a program may access. SBOM documents included components. Reproducible builds make artefacts auditable. In training, these concepts are framed as engineering discipline, not bureaucracy.

34. Update v7.8.5: deliver programs, not only run them

What learners should additionally understand

A program can consist of source, runtime, manifest, launcher scripts, GPU plan, Web overlay and verification reports. Delivery is part of engineering.

The four package forms

FormMeaning
full-runtimecomplete runtime bundle
native-subsetsmaller native-oriented package
zipappsingle-file Python zip application
directory-bundleinspection-friendly folder layout

Commands for training

python -m keim exe-status --json
python -m keim exe-pack examples/agenten_zweige_v78_1_gpu_aware/src/main.keim --out build/agenten_bundle --name agenten_zweige --target auto
python -m keim exe-verify build/agenten_bundle --json
python -m keim exe-run build/agenten_bundle

New memory rule

Source is not the package. A release must show what it contains, how it starts, what it requires and how it was verified.
